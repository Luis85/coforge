# CoForge studio design

## Operating context

A streamer works inside a resizable Obsidian leaf, often while broadcasting. Native theme compatibility, readable data and explicit external-effect controls are durable constraints. The owner selected a more expressive studio with stronger color, larger summaries and more visual emphasis on 2026-10-28.

## Visual system

Use the native interface font and theme palette. Give primary page titles, important decision counts and current selections enough scale and color to be recognized at a glance. Accent surfaces identify actionable context; semantic success, caution and danger colors always accompany text. Quiet neutral surfaces carry extended reading and configuration.

Keep the standard centered 1440px operating frame and existing leaf-relative gutters. Board, public displays and native integration settings retain their distinct task-appropriate frames. Use open section composition and separators; reserve containers for focused tasks, selected records, durable recovery and protected actions.

## Task hierarchy

The studio navigates by Build & Improve, Stream, Community and Insights, in that order. Stream and community work are channel-wide. CoWorkers are reusable across the vault; teams, councils, backlogs, workflows and repository settings retain their project context. Local navigation divides distinct tasks; it neither saves drafts nor dispatches work.

The Council uses four primary task tabs: Ask, Activity, Setup and Automation.
Each exposes short, visible secondary page navigation. Keep these rows on one
line with contained horizontal overflow in narrow leaves; use the established
page-navigation semantics and visible keyboard focus. All existing internal page
IDs remain stable. Ask leads with the question and its audience; Activity leads
with human task titles and attributed published answers. Setup shows observed
prerequisites and actions rather than permanently repeating first-use instructions.
Routine execution administration belongs in Activity; vault-wide storage scope
must be explicit. Status announcements carry concise state changes, with timestamps
and extended evidence outside the live region.

Project settings is a persistent navigation entry at the bottom, outside the
collapsible task groups. It owns General, Requests, Repository, Agent workflow,
Runtime, and Data & examples. Agent workflow retains Workflow runs, Herdr
workspaces and Workflow settings as nested tasks. Keep one Project settings H1;
use subordinate headings for its tasks and retain explicit project/workflow save
boundaries. Label the all-project private backup separately from project-specific
sample replacement. Integration credentials remain in native Obsidian settings.

The expanded project navigation is 240px wide. Keep destination labels on one line
and use compact spacing in shorter panes; section grouping remains accessible.
Genuinely short panes may scroll without clipping controls. Project identity and
private visibility live in the switcher; work pages do not repeat a context banner.
The backlog proceeds from its heading to filter tabs and toolbar, without a
separate decision-summary section. Review and moderation counts stay in the tabs.

Lead each page with its outcome, current context and useful next action. A summary must explain a decision or a data boundary. Recorded, observed, planned, reported, manually entered and unavailable values remain distinct. Never infer a trustworthy total from incomplete coverage.

## Interaction and state

Use native buttons, labelled fields and navigation landmarks with visible keyboard focus. Preserve drafts through guarded navigation. Selection and focus have separate treatments. Keep controls operable in narrow leaves; long labels wrap and tabular content has an explicitly labelled scroll region.

Public capture roots use only their public projection and receive no private host controls. External mutations require the existing confirmation and recovery mechanisms. Color, layout and copy may clarify those mechanisms but cannot bypass them.

Motion is limited to short state transitions and respects reduced motion. No page-load choreography delays operation. Review both themes and wide/narrow leaves using current rendered screenshots and accessibility tests.
