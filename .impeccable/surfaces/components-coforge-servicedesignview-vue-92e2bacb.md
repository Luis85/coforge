# Service Design surface

Mode: Operate. Extend CoForge's established studio design. The owner confirmed one
project blueprint, a grid, entity creation/editing and canonical linked Markdown.

## Direction contract

THESIS: Make service delivery inspectable across a customer journey, with the
blueprint itself leading the page and explicit authoring beside the saved map.

OWN-WORLD: Inherit DESIGN.md: native interface font, Obsidian theme colors, quiet
neutral work surfaces, restrained accent selection, existing studio buttons and
leaf-relative frame. No new palette, imagery, typography or decorative motion.

STORY: Name the service and customer goal, add ordered journey steps, map the five
layers, connect people/systems/touchpoints, then record pain points and improvements.

FIRST VIEWPORT: Existing studio navigation at left; Service Design title, purpose
and Refresh above the saved blueprint title, entity toolbar and semantic table.
Empty states give the immediate creation action. The editor follows the map;
opening it moves keyboard focus to its title. Narrow panes scroll the table only.

FORM: Owner-approved blueprint grid inside the existing studio; a precise local
extension, so no concept tournament or seed applies. Signature interaction is
adding a typed entity directly at its journey/layer intersection, preserving draft
and project identity until an explicit successful save.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish
review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

No raster assets ship. DESIGN.md remains the inherited authority. Acceptance and
cross-perspective evidence live in the Service Design improvement plan.
