# Stabilization: journey and information architecture review

- Status: implemented; final browser and host qualification recorded in the parent stabilization task.
- Product source: `BRIEF.md`, including the Council owner decisions and streaming workspace increment.
- Requirement and interaction IDs: `design/traceability.json` has no `req-*` or `vi-*` entries. These are stabilization changes to existing journeys, not invented acceptance obligations.

## Review method and limits

Reviewed every Studio destination, private drawer, Council workspace, native integration settings surface and public projection against its entry point, one user goal, next action, state ownership and external-effect boundary. The view catalogue in `docs/components/views/` is the durable per-view contract; its generated sitemap maps the actual navigation state. This document records journey-level reasoning and findings.

Source review establishes the intended contract; browser simulation and in-memory host tests establish only the exercised behavior. Neither qualifies a live Twitch account, OBS installation, provider invocation, external game repository, production vault nor native Obsidian rendering. Final command results and screenshot paths belong in the parent stabilization task and PR evidence.

## Findings and implementation decisions

| Finding | User consequence | Resolution |
| --- | --- | --- |
| Stream studio put broadcast operation, live monitoring, installation/setup, scene editing, music, public capture launchers and history into one long page. | The next on-air action competed with maintenance and preparation tasks. | Six focused subpages: Broadcast, Setup, Scenes, Music, Public displays and History. Keep broadcast controls and live observations together; keep setup drafts mounted during local navigation. |
| Stream chat put the conversation beside connection credentials, channel metadata/branding and moderation forms. | Conversation space competed with account setup; Configure Twitch could only reopen the same crowded page. | Chat, Twitch settings and Bot messages share the same subpage navigation seam. Contextual moderation stays with Chat; Configure Twitch explicitly selects Twitch settings. |
| Stream studio and Stream chat both embedded the channel metadata editor. | Two visible authoring locations obscured where channel settings belonged. | Canonical channel metadata editor under Twitch settings; stream preparation links there. Guided setup retains its existing authorization/readiness steps. |
| Council global execution mutations appeared above definition authoring and every other task. | Creating definitions visually competed with designating an executor and resuming work. | Execution controls live with Run monitor. Definitions remain authoring; private Definition folders get their own page. Intake and submissions remain separate. A nonexecutor sees a prerequisite explanation and Open Run monitor shortcut before admission or inbox/folder changes; navigation does not designate the desktop. |
| Council folders and definitions shared one page but represented different tasks and conflict/revision boundaries. | Storage migration competed with specialist editing. | Definition folders is a separate page; its unsaved draft survives local page switches. Preview/save guards remain authoritative. |
| Workflow monitoring embedded Herdr executable/session/workspace administration. | Following one request required passing native workspace management unrelated to that run. | Workflow runs retains execution, checkpoints, attempt history and correlated recovery; Herdr workspaces owns manual workspace/agent operations. |
| The sidebar called project configuration “Studio settings”; native settings pointed providers/models/run limits there. | Users could follow an outdated destination and scope. | Use Project settings consistently, expose its current state, and point provider/model/prompt/limit editing to Workflow settings. Correct earning-rule guidance to Community settings. |
| Local subpage navigation used unrelated Council buttons and Stream tab markup. | Selection and control styling varied between workspaces. | Shared `CfSubpageNav` uses semantic native buttons in a labelled navigation landmark, one `aria-current="page"`, normal keyboard activation and a shared spacing seam. |

No new product capabilities or host permissions were introduced. Page changes never invoke a provider, start a broadcast, auto-play music, accept code or publish an Idea. Existing definition/run snapshots, private/public projections and explicit host confirmation boundaries remain in their original application services.

## Meaningful regression evidence for new page boundaries

- `stabilization-navigation-ui.test.ts`: broadcast page isolation, preserved OBS settings draft, separate Herdr administration, separate Twitch configuration and Configure Twitch routing; no provider invocation or hidden save.
- `council-navigation-ui.test.ts`: definition folders isolated from authoring/monitoring and open on entry, preserved folder draft, fresh nonexecutor prerequisite route and execution stays paused.
- Both navigation test files were run red before their corresponding implementation, then green. Initial failures were missing page navigation / competing panels visible, rather than placeholder assertions.
- `broadcast-ui.test.ts`: existing explicit fake-host setup → prepare → live → BRB → resume → stop journey retained with focused navigation and history export.
- `stabilization-subpages.spec.ts`: browser keyboard activation, current-page semantics, light/dark and wide/narrow captures, contained overflow and axe checks for every added subpage. The parent task records its executed result, not this source declaration.
